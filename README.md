# 우리 반 퀴즈런 · 6-B 우승 시상식과 경기 결과

5-C의 물 차오름과 스펀지바 충돌을 기반으로 합니다. 교사 1명과 학생 최대 30명이 접속할 수 있으며 혼자 하기에서는 컴퓨터 토끼와 라운드를 진행합니다.

## 실행

Node.js 22 이상과 Python 3을 사용합니다.

```sh
npm install
npm run build
npm run dev
npm test
npm run test:online
```

로컬 주소는 `http://127.0.0.1:4175`입니다. 교사가 방을 만들고 QR이나 참가 링크로 초대합니다. 퀴즈와 경기 규칙을 고른 후 교사가 게임을 시작합니다. 학생은 이동·질주·점프로 발판을 고릅니다. 탈락하면 이전·다음 버튼으로 관전 대상을 바꾸고 경기장을 드래그해 카메라를 돌릴 수 있습니다.

## 경기 흐름

- 1라운드는 장애물이 없고, 2라운드는 항상 등장합니다. 3라운드부터는 기본 90% 확률이며, 장애물이 없었던 라운드 다음에는 반드시 등장합니다. 왕복 스펀지바, 회전 스펀지바, 물 차오름 중 한 가지 또는 서로 다른 두 가지를 뽑습니다. 직전 라운드와 같은 조합은 추첨에서 제외합니다. 가로·세로 동시 왕복도 왕복 한 종류로 계산합니다. 장애물과 캐릭터 간 충돌은 각각 켜거나 끌 수 있습니다. 온라인에서는 서버에서 패턴과 막대별 방향 및 타이밍을 결정합니다.
- 이동 시작과 함께 경고가 나옵니다. 회전 스펀지바는 이때부터 1초간 상승하고, 정상 높이에 도달한 후 회전과 충돌을 시작합니다. 왕복 막대도 경고 1초 뒤 출발합니다. 막대가 들어오는 동안은 안전하고 출발하면 정답 판정 순간과 공개 후 생존 구간에도 충돌이 이어집니다. 캐릭터 간 충돌 역시 켜 둔 경기에서는 마감 전후에 계속 적용됩니다.
- 물 차오름 3초 전에 서버 시각을 기준으로 중앙에 3 → 2 → 1 경고가 표시됩니다. 이동 제한이 3~4초라 경고와 상승을 모두 마치기 어려운 경우에는 스펀지바만 등장할 수 있습니다.
- 물이 차오르면 일반 바닥이 잠기고 선지 발판은 수면 위에 남습니다. 이동 중 입수한 토끼는 가장 가까운 선지 발판으로 복귀합니다. 수면은 정답 공개 후 유지되고 경기장 복원에 맞춰 내려갑니다.
- 마감 시 서버가 수평 위치로 답을 확정합니다. 이후에도 이동과 점프가 가능합니다. 같은 시점에 오답 목숨이 차감되고 오답 발판과 일반 바닥의 물리적 지지가 사라지며, 침수 애니메이션이 시작됩니다. 정답 공개 이후 기본 5초의 생존 구간이 이어집니다. 복원 시 왕복 막대는 사라지고 회전 막대는 충돌과 회전을 끈 상태로 내려갑니다.
- 선택 중 추락은 목숨 차감 없이 복귀합니다. 오답 또는 정답 공개 이후의 추락은 같은 라운드에서 합산 최대 한 번만 차감됩니다. 물에 빠진 생존자만 복원 뒤 안전한 위치로 돌아오며, 다른 학생은 수평 위치를 유지합니다. 수동 대기 중에는 기존 이동 규칙으로 플레이할 수 있습니다.
- 온라인에서는 이벤트 종류, 시작 시각, 방향과 속도, 수면 상승 설정만 라운드 상태에 보냅니다. 학생 화면은 같은 시각과 운동식을 사용해 장애물을 그립니다. 위치 전송 목표 주기는 기존과 동일한 100ms입니다.

## 경기 종료

마지막 추가 생존과 경기장 복원 후 서버가 최종 명단과 시상식 시작 시각을 확정합니다. 우승자가 있으면 기존 경기장 중앙에서 약 5초간 시상식이 진행됩니다. 교사와 학생은 같은 최종 명단을 확인할 수 있습니다. 교사의 다시 하기는 방을 유지하며 이전 퀴즈와 설정으로 새 경기를 시작합니다.

## 효과음

메인 화면과 경기 화면의 소리 버튼은 이 브라우저에 설정을 저장합니다. 기본은 OFF이며 브라우저 정책에 따라 클릭이나 키 입력이 있은 뒤 재생을 시작합니다. 효과음은 `sound.js`에서 직접 합성하고 외부 음원을 내려받지 않습니다. 온라인에서는 서버의 경기 상태를 각 학생 브라우저가 받아 개별적으로 재생합니다.

## 스펀지바 모델 재생성

Blender 4.3.2에서 `blender -b -P assets/make_sponge_bar.py`를 실행하면 `assets/sponge-bar.glb`가 생성됩니다. `npm run build`로 새 모델을 게임 HTML에 반영합니다. GLB는 360개 삼각형과 512×64 PNG 하나를 포함합니다. 왕복과 회전 막대는 같은 모델을 쓰며, 막대 길이를 바꿀 때에도 둥근 끝의 반지름을 유지합니다.

## 스펀지바의 지속 충돌

왕복·회전 막대에 같은 이동 충돌 계산을 적용합니다. 접촉할 때마다 막대 반대편으로 관통하는 이동을 막고, 움직이는 막대를 따라 토끼의 위치를 보정합니다. 발이 막대 위로 올라가면 점프로 통과할 수 있고, 내려올 때 막대 위에 닿으면 착지합니다. 선지 발판을 넓혀 명목상 가로·세로 간격을 각각 5.58 → 3.28, 4.52 → 2.22로 줄였습니다. 같은 크기를 클라이언트 모델과 서버 판정에 사용합니다. 스펀지바 폭은 .80이며 쿠션 모델과 물리 판정에 같은 치수를 사용합니다. 일반 바닥과 선지 발판에서 모두 기존 점프로 넘을 수 있으며 달려서 막대 아래로 통과할 수는 없습니다.

가로·세로 패턴에서는 두 막대가 서로 다른 타이밍으로 움직입니다. 교차 지점에서는 두 접촉을 함께 계산하고 수평 보정량을 제한합니다.

공유 충돌 계산은 `arena-event.js`에 있습니다. 학생 기기는 충돌을 즉시 예측하고 서버는 받는 이동 입력과 서버 시간으로 최종 위치를 계산합니다. 기존 10Hz 위치 교환을 사용합니다.

## 튜닝 및 테스트

- `arena-event.js`의 `config`에 확률, 왕복·회전 속도, 충돌 보정량, 침수 생존 시간, 복원 시간을 모았습니다. 이벤트 경로 및 충돌은 같은 파일, 서버의 수면 판정은 `server/hazards.mjs`, 장애물 모델은 `sponge-bars.js`에 있습니다.
- `npm test`와 `npm run test:online`에서 조작, 데이터, 두 장애물의 경로와 회피, 공중 정답, 생존 중 추락, 중복 차감 방지, 부활 위치, 수동 진행, 재접속 및 최종 우승 판정을 검사합니다.
- `npm run test:load`는 기본 600초 동안 학생 30명이 연결되는 로컬 WebSocket 시뮬레이션입니다. `QUIZRUN_LOAD_SECONDS`로 실행 길이를, `QUIZRUN_LOAD_CONTACT=0`과 `QUIZRUN_LOAD_OBSTACLES=0`으로 충돌과 장애물을 조절할 수 있습니다. 바이트 카운트는 위치 묶음의 JSON 본문 합계입니다.
- Canvas 폴백은 렌더링 상한을 760×500으로 낮췄습니다. 학교 태블릿의 실제 WebGL 성능과 교실 Wi-Fi는 별도 검증이 필요합니다.

## 7-A 정식 배포

프런트는 전용 GitHub 저장소에서 연결한 Vercel 정적 사이트로 배포합니다. 브라우저의 HTTPS API와 WSS 연결은 Cloudflare Worker로 직접 접속합니다. 방 데이터와 WebSocket 세션은 Worker에 바인딩된 SQLite Durable Object `ROOMS`가 관리합니다.

| 설정 | 위치 | 입력값 |
| --- | --- | --- |
| Worker 이름 및 SQLite 클래스 | `wrangler.jsonc` | `churrri-quizrun-online`, `ROOMS` → `Room`, 마이그레이션 `v1` 유지 |
| `ALLOWED_ORIGINS` | `wrangler.jsonc`의 `vars` | 승인한 Vercel HTTPS origin만 입력. 여러 개라면 쉼표로 구분 |
| `QUIZRUN_API_ORIGIN` | Vercel 프로젝트의 Production 환경변수 | 본인 계정의 Worker HTTPS 주소. 경로, 쿼리, 토큰 없이 입력 |
| 정적 산출물 | `vercel.json` | `python3 build.py --require-api-origin` 실행 후 `public/` 배포 |

1. 새 퀴즈런 전용 GitHub 저장소를 만들고 이 프로젝트만 올립니다. 전용 Vercel 프로젝트에 연결해 예정된 Production URL을 확인합니다.
2. 본인 Cloudflare 계정에서 `npm install`, `npx wrangler login`을 실행합니다. `ALLOWED_ORIGINS`에 Vercel Production 주소를 경로나 마지막 슬래시 없이 적고 `npm run deploy:worker`로 배포합니다. 본인 계정의 고정 `workers.dev` 주소나 소유한 HTTPS 서브도메인을 사용합니다.
3. Vercel의 Production 환경변수에 `QUIZRUN_API_ORIGIN`을 설정한 뒤 연동한 저장소를 배포합니다. 주소 없이 빌드하면 오류가 나므로 운영 프런트가 실수로 Vercel 자체에 방 API를 요청하는 일을 막습니다. Preview 환경을 사용할 때도 연결할 주소와 허용 origin을 별도로 맞춥니다.
4. 교사·학생이 실제 Vercel 주소에 접속해 QR과 방 코드로 같은 방에 들어옵니다. 브라우저 네트워크에서 `OPTIONS 204`, 방 생성 `201`, WSS 업그레이드 `101`을 확인합니다. 학생 화면을 새로고침해 참가자와 라운드가 복구되는지 확인합니다. 다른 주소에 저장된 퀴즈는 JSON으로 옮깁니다.

재접속 티켓은 20초 동안 한 번만 사용할 수 있습니다. 같은 탭에서 참가 세션을 이용해 새 티켓을 요청하며, 학생의 연결 유예 시간은 90초입니다. 서버가 위치·라운드·목숨을 복구하는지 실제 배포 환경에서 확인합니다. `QUIZRUN_API_ORIGIN`은 브라우저에 포함되는 공개 설정입니다.

`npm run test:load`는 로컬 Workers 런타임에 학생 30명과 교사 1명을 연결합니다. `QUIZRUN_LOAD_SECONDS=135`로 짧은 시험을 실행할 수 있습니다. RTT는 WebSocket ping 왕복이고 메모리는 로컬 workerd RSS입니다. 결과에는 Cloudflare 실서비스나 학교 Wi-Fi의 수치가 포함되지 않습니다.
